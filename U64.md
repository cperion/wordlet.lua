# wordletkit U64

Exact unsigned and signed 64-bit operations over a pair of 32-bit words. This is bootstrap tooling,
not part of the Wordlet compiler's own type system: the compiler uses it so that evaluating a `U64` or
`I64` expression is exact rather than approximate.

A LuaJIT number is a double, so it represents every 32-bit word exactly but not a 64-bit value. Each
operation therefore takes and returns the two words, and only uses sums and products a double
represents exactly. Multiplication decomposes each operand into 16-bit limbs; division is a restoring
loop over 64 bits that keeps the bit shifted out of the high word, because with a large divisor the
shifted remainder can exceed 64 bits.

```
local u = require("wordletkit.u64")
assert(u.add(0, 4294967295, 0, 1) == 1)                 -- the low word carries: 2^32
assert(select(1, u.mul(0, 4294967295, 0, 4294967295)) == 4294967294)
assert(u.tostring(4294967295, 4294967295, true) == "-1") -- signed words are two's complement
```

Unsigned arithmetic wraps at 64 bits. The signed operations read the same words as two's complement
and follow C's division rule: the quotient truncates toward zero and the remainder takes the dividend's
sign, with the one case C leaves undefined defined here, so the most negative value divided by -1
wraps to itself. `sar` keeps the sign bit. `tofloat` produces the nearest double, rounding once with a
tie to even, which is what a conversion from `U64` to `F64` needs.

`check(word)` validates one 32-bit word. Every other function takes two words per operand.

| Function | Result |
| --- | --- |
| `add`, `sub`, `mul`, `neg`, `pow` | two words, wrapping at 64 bits |
| `divmod`, `sdivmod` | quotient and remainder as four words |
| `shl`, `shr`, `sar` | two words; `sar` is arithmetic |
| `band`, `bor`, `bxor`, `bnot` | two words |
| `lt`, `le`, `eq` | unsigned comparison; `slt`, `sle`, `spositive` are signed |
| `iszero`, `tostring(high, low, isSigned)`, `tofloat` | a Lua value |
