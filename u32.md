# u32 reference semantics and implementation notes

`require("wordletkit.u32")` provides checked concrete operations using LuaJIT numbers and its built-in
bit module. Inputs must be finite integral numbers in 0..4294967295. These are host helper functions,
not Wordlet proxies or compiler diagnostics; a frontend translates validation failures to source spans.

API: check, add, sub, neg, mul, div, mod, pow, band, bor, bxor, bnot, shl, shr. All results are unsigned
Lua numbers in the same range. div/mod reject zero. pow(a,0)=1, including pow(0,0). Shift counts at
least 32 yield zero; negative/out-of-range operands reject before shifting. There is no signed u32.

## Exact host arithmetic

Addition/subtraction fit exactly in a double before reduction modulo 2^32. Multiplying two arbitrary
u32 values does NOT. The kernel splits each operand into 16-bit limbs:

```
a = ah * 65536 + al
b = bh * 65536 + bl
low_product = al * bl
cross = (ah * bl + al * bh) mod 65536
result = (low_product + cross * 65536) mod 4294967296
```

Every intermediate in this computation fits the exact integer range of a double. The discarded high
product contributes only multiples of 2^32. pow uses repeated squaring with this exact multiplication.
LuaJIT bit results are signed 32-bit numbers; add 2^32 to negative results to normalize them. LuaJIT
shifts mask the count, so test count>=32 BEFORE calling the host shift operation.

For u32 division, floor(a/b) is safe at this bounded precision: the distance to an adjacent wrong
integer quotient is greater than the floating division error for 32-bit integer operands. The
remainder also remains exact. Do not generalize these arguments to u64 or floating-point source types.

A lexer should range-check literal accumulation digit by digit rather than first converting an
arbitrarily long integer to an inexact Lua number. Before `n = n*base+digit`, reject when
`n > floor((4294967295-digit)/base)`. A leading minus is the typed unary operation after literal parsing.

## C lowering obligations

Require uint32_t, uint64_t and bool from stdint.h/stdbool.h. Force unsigned widening so ordinary C
integer promotions cannot turn arithmetic into signed overflow. Representative expressions are:

```c
(uint32_t)((uint64_t)a + (uint64_t)b)
(uint32_t)((uint64_t)a - (uint64_t)b)
(uint32_t)((uint64_t)a * (uint64_t)b)
(uint32_t)(UINT64_C(0) - (uint64_t)a)
b >= 32 ? UINT32_C(0) : (uint32_t)((uint64_t)a << b)
b >= 32 ? UINT32_C(0) : (uint32_t)((uint64_t)a >> b)
```

Division/remainder use evaluated immutable operands. Emit a zero check and abort before evaluating
the partial operation. Never hoist it out of the successful guard region. Evaluating a statically
known zero divisor is a source rejection, not constant folding to an invented value.

Comparison yields bool; equality is type-checked before emission. bool is not a numeric conversion.
Runtime pow is an unsigned repeated-squaring helper, not C's floating pow(). Its local loop need not
be represented as source recursion; it is an implementation of a primitive with a fixed contract.

## Validation

Bootstrap tests cover arithmetic edge cases, unsigned bit normalization, shift counts and negative
input/zero-divisor rejection. They also compare mul to an independent bit-serial modular multiplication
on a fixed corpus. Future compiler C tests must independently exercise these cases end-to-end; calling
the same host kernel twice is not differential compiler validation.
